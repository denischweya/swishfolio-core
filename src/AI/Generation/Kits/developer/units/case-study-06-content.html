04In the code

Retries are a feature, not a risk.

The core of the engine is short on purpose. A payout claims its idempotency key, posts a balanced transfer to the ledger and writes an event to the outbox, all in one transaction. Call it twice and the second call does nothing.

  • 94% test coverage on the payouts package
  • Property tests: the ledger always balances to zero
  • Replayed three weeks of production traffic before launch
payouts/settle.go
// Settle is safe to call any number of times.
func (s *Service) Settle(ctx context.Context, req Request) error {
  return s.db.Tx(ctx, func(tx Tx) error {
    if seen, err := tx.Claim(req.Key); err != nil || seen {
      return err // replay: already settled
    }
    if err := tx.Post(ledger.Transfer(req.Seller, req.Amount)); err != nil {
      return err
    }
    return tx.Outbox("payout.requested", req)
  })
}
